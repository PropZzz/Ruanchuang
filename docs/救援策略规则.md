# 救援策略规则

救援策略使用 `contracts/scheduling/v1/rescue-strategies.json` 作为唯一规则来源。`schemaVersion` 保持为 `1`，当前 `policyVersion` 为 `1`。三种策略共享硬约束阶段，只在硬约束通过后计算软评分。

## 统一处理顺序

硬约束顺序固定为：规范化输入、锁定固定日程、计算工作窗口、检查依赖、处理截止时间。没有提供工作窗口时不虚构默认空档；固定条目不移动、不缩短、不被普通任务覆盖。未知、失败或循环依赖产生 `dependency_blocked`，硬截止不能使用迟到回退。

硬问题优先于评分。`fixed_conflict`、`no_slot`、`dependency_blocked` 和硬截止失败都计为硬问题。方案推荐依次按硬问题数升序、总分降序、策略固定顺序（`protectDeadline`、`protectRecovery`、`minimizeChanges`）选择。软分数不得抵消硬约束失败。

解释码生成顺序固定为 `deadline_proximity`、`priority`、`energy_fit`、`kept_baseline`、`fixed_conflict`，并去重。

## 策略矩阵

### `protectDeadline`：优先保住截止时间

- **场景：** 有临近截止的紧急任务，首先降低逾期概率。
- **固定日程：** `fixed` 条目不移动、不缩短、不覆盖；越出窗口或彼此重叠时保留原条目并产生 `fixed_conflict`。
- **基线：** 允许在合法空档内重排非固定基线条目，只要不违反窗口、依赖和硬截止。
- **截止：** 紧急任务和其他带截止任务按同日截止时间升序优先；硬截止没有迟到回退，软截止最早合法回退产生 `miss_due`。
- **低能量：** 低负荷任务获得能量匹配分；能量分不能越过紧急度或硬约束排序。
- **移动：** 对稳定 ID 的基线条目比较 ID、开始时间和时长；缺失、开始时间变化或时长变化超过 0.1 分钟各计 1 次。新增紧急任务和恢复块不计入。
- **恢复与风险：** 不主动插入恢复块，实际恢复分钟数为 0；`overdueRisk` 使用统一截止问题公式，`urgency = 1 - overdueRisk`。
- **解释码：** 按固定顺序去重；带截止任务使用 `deadline_proximity`，优先级影响候选使用 `priority`，能量匹配使用 `energy_fit`，未移动基线使用 `kept_baseline`，固定日程限制候选使用 `fixed_conflict`。

### `protectRecovery`：优先保留恢复时间

- **场景：** 用户低能量、连续被打断或需要避免任务堆叠，优先保留可执行的恢复空间。
- **固定日程与基线：** 固定条目同样不可移动；非固定基线可在合法空档内重排并优先保持不动。恢复块不能越出窗口或覆盖固定条目。
- **截止与能量：** 仍先满足硬截止；软截止迟到产生 `miss_due`，不能用恢复偏好掩盖硬失败。目标能量降低一档（最低 `veryLow`），可行候选中优先低/中负荷。
- **移动：** 使用相同稳定 ID、开始时间和时长比较公式；新增恢复块不计入移动数。
- **恢复与风险：** 仅在扣除固定和已选任务后找到连续 15 分钟合法空档时插入恢复块；找不到时恢复分钟数为 0 且保留可行任务结果。`overdueRisk` 与其他策略相同，不因恢复缓冲降低风险。
- **解释码：** 实际插入恢复块且负荷匹配降低后的能量时使用 `energy_fit`；保持基线使用 `kept_baseline`；固定日程限制候选使用 `fixed_conflict`。恢复块不使用自由文本解释码。

### `minimizeChanges`：尽量少动原计划

- **场景：** 原计划大部分仍可执行，只需在不破坏既有安排的前提下加入紧急任务。
- **固定日程与基线：** `fixed` 条目和目标日全部基线条目都锁定，不移动、不缩短、不覆盖；锁定导致候选受限时产生 `fixed_conflict`。
- **截止与能量：** 紧急任务先尝试硬截止内的合法空档；无空档产生 `no_slot`/硬截止问题，不能移动基线换取更高分。软截止迟到只产生 `miss_due`；能量只作紧急任务空档的软分。
- **移动：** 合法方案移动数为 0；候选缺少或改变基线 ID 时，每个受影响条目按统一公式计数并产生诊断。新增紧急任务不计入。
- **恢复与风险：** 不主动插入恢复块，实际恢复分钟数为 0；基线锁定造成的紧急任务迟到仍计入统一 `overdueRisk`，不能被稳定性高分抵消。
- **解释码：** 保持基线使用 `kept_baseline`；带截止紧急任务使用 `deadline_proximity`；按优先级选槽使用 `priority`；能量匹配使用 `energy_fit`；锁定基线限制候选使用 `fixed_conflict`。

三种策略都使用相同的稳定 ID、开始时间和时长比较来计算移动数。恢复分钟数只统计实际插入的恢复块，找不到合法位置时为 `0`。

## 指标与权重

所有指标先限制到 `[0, 1]`，总分四舍五入到 6 位：

```text
overdueRisk = missedDeadlineCount / max(1, dueTaskCount)
urgency     = 1 - overdueRisk
priority    = placedPrioritySum / (5 * max(1, taskCount))
energyFit   = 1 - weightedLoadMismatch / max(1, placedTaskCount)
stability   = 1 - movedEntryCount / max(1, baselineEntryCount)
recovery    = min(recoveryMinutes / recoveryBufferMinutes, 1)
score       = Σ(metric × strategyWeight)
```

负荷映射为 `low=0`、`medium=1`、`high=2`，目标能量的距离除以 2 后计入 `weightedLoadMismatch`。分片任务按原任务 ID 聚合。`missedDeadlineCount` 包含 `miss_due` 和 `overdue`；请求日在截止日前的任务不计入当日截止风险。`recoveryBufferMinutes` 为 15。

权重保持如下：

| 策略 | urgency | priority | energyFit | stability | recovery |
| --- | ---: | ---: | ---: | ---: | ---: |
| `protectDeadline` | 0.55 | 0.25 | 0.10 | 0.10 | 0.00 |
| `protectRecovery` | 0.20 | 0.10 | 0.35 | 0.10 | 0.25 |
| `minimizeChanges` | 0.25 | 0.15 | 0.05 | 0.55 | 0.00 |

硬约束、固定日程和依赖诊断始终先于这些权重处理。
