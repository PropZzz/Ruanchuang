# 时序智配 Design System

> 全局设计系统（Single Source of Truth）
>
> 版本：2026-09-01 · 适用：`Ruanchuang-main` Flutter 客户端与并行 Web 版本

## 0. 产品与设计定位

### 产品类型

时序智配是面向高压知识工作者的**个人效率与日程救援工作台**。它把日程、任务、精力/情绪、团队协作和复盘放在同一时间上下文中，核心价值不是“替用户自动做决定”，而是：

```text
突发任务输入
  -> 三种可解释的日程救援方案
  -> 比较代价与恢复缓冲
  -> 用户确认
  -> 日程持久化与事件记录
  -> 可撤销与周/月复盘
```

### 使用场景与受众

- 开发、研究、学习等高认知负荷工作：临时需求或会议变化后保护截止时间。
- 个人精力管理：根据当前能量和情绪保留恢复缓冲，避免连续过载。
- 小团队协作：在共享边界内查看成员状态、忙碌块和可用窗口。

### 设计主张

1. **冷静可信**：像工作台，不像营销落地页；先显示事实、约束和代价，再显示建议。
2. **时间地图优先**：用户在同一视图中理解“现在、接下来、冲突和恢复”。
3. **人保留控制权**：生成草案不等于写入日程；每次救援都要比较、确认、可撤销。
4. **状态诚实**：远端成功、本地兜底、待同步、无数据、冲突和预留接口必须可区分。
5. **逐步适配**：个人效率是主路径，团队、目标、复盘和设置自然延伸，不改变既有业务模型。

### 适用技术边界

- Flutter 3.38 / Dart 3.10；Material 3 原生组件优先，`CupertinoIcons` 与 Material 图标作为统一图标来源。
- 复用 `DataService`、`RemoteDataService`、`CompositeDataService`、FastAPI、SQLite 和本地优先策略。
- 组件只接收模型、渲染状态和回调；网络、数据库和全局单例调用由页面控制器完成。
- 本文只定义视觉、交互、信息架构和状态呈现，不扩展调度算法、后端路由、硬件或传感器能力。

#### 对比度规则

- 主文字与正文表面至少达到 4.5:1；大标题至少 3:1。
- `#6E6E73` 在白色表面约 5.07:1，可用于辅助正文；深色使用 `#98989D`。
- `#007AFF` 在白色上的对比度不足以承担小字号文字，因此小字号链接使用 `actionText`；按钮文字使用更深的 `#0066CC` 兼容变体或提高字号/字重后再复核。
- `recovery`、`pressure`、`risk` 默认作为图标、色块或浅色状态底；不要直接放白色小字。状态必须同时有图标或文字，不得只用红/绿区分。
- 深色模式单独检查，不通过“反转颜色”推导；边框、焦点环、禁用态和错误态在两种主题都要可辨识。

### 2.3 字体与数字

```text
正文/界面：PingFang SC, Noto Sans SC, system-ui, sans-serif
品牌/少量区块标题：NotoSerifSC, PingFang SC, serif
计时/数据：上述字体 + FontFeature.tabularFigures()
```

不引入远程 Google Fonts，避免 Flutter Web 首屏字体闪烁和中文回退不一致。正文基线为 16sp，辅助文字不低于 12sp，字距保持平台默认（`letterSpacing: 0`）。

| 角色 | 大小/行高 | 字重 | 使用场景 |
| --- | --- | --- | --- |
| `pageTitle` | 28/34 | 700 | 页面标题；不用营销型超大 Hero。 |
| `sectionTitle` | 22/28 | 700 | 工作区区块标题。 |
| `cardTitle` | 17/24 | 600 | 卡片、任务、列表项标题。 |
| `body` | 16/24 | 400 | 正文、表单、时间块主要信息。 |
| `bodySmall` | 14/20 | 400 | 辅助说明和时间刻度。 |
| `label` | 12/16 | 600 | 标签、状态和分组标题。 |
| `metric` | 28/32 | 700 | 能量、剩余时间、移动任务数；使用等宽数字。 |
| `caption` | 12/16 | 400 | 来源、更新时间和非关键元数据。 |

支持系统字体放大和动态文本；标题可自然换行，必要时用 Tooltip/展开查看完整内容，不用强制截断关键任务名。

### 2.4 间距、圆角与层级

| 令牌组 | 值 | 规则 |
| --- | --- | --- |
| `space` | 4, 8, 12, 16, 24, 32, 40, 48, 64 | 所有间距为 4/8dp 节奏。 |
| `pageInset` | 手机 16、平板 24、桌面 32 | 使用约束布局，桌面内容最大宽度 1320。 |
| `controlRadius` | 10-12 | 按钮、输入框、筛选器和小控件。 |
| `componentRadius` | 14-16 | 任务卡、列表容器、时间块面板。 |
| `pageRadius` | 24 | 只用于大的工作区表面或页面容器。 |
| `modalRadius` | 20 | Dialog/BottomSheet 顶部。 |
| `elevation` | 0 / 1 / 2 | 默认无阴影；浮层只用小范围、低对比阴影。 |
| `blur` | 12-14px | 只用于 `GlassSurface`；不作为主要对比来源。 |

禁止无限圆角包裹整段文本、嵌套卡片和复杂阴影。标签/Chip 可以使用较圆形状，但不把普通按钮做成药丸。

`GlassSurface` 的默认实现：浅色 `surface` 约 72% 不透明度、深色约 62%，`BackdropFilter` 模糊 12-14px，叠加 1px 低对比边框和小范围阴影；在不支持模糊或开启减少透明度时回退到不透明 `surface`。任务、能量、日程状态和救援摘要之外，不扩散毛玻璃。

### 2.5 图标与视觉元素

- 优先 `CupertinoIcons`，无等价图标时使用 Material 3 图标；同一层级保持同一图标家族和线性/填充风格。
- 尺寸令牌：`iconSm=16`、`iconMd=20`、`iconLg=24`、`iconXl=32`；图标视觉小于 44 时扩大命中区域。
- 禁止使用 Emoji 作为导航、设置、状态或操作图标；品牌图标使用仓库正式资源并保留比例和留白。
- 独立图标按钮必须有 `Tooltip`、语义名称和 selected/pressed/expanded 状态；与可见文字重复的装饰图标隐藏于辅助技术树。

## 3. 响应式壳层与导航

### 3.1 断点

| 宽度 | 壳层 | 主要内容 | 弹层与操作 |
| --- | --- | --- | --- |
| `<720px` | 顶部状态栏 + 五项 `NavigationBar` | 单列；优先当前任务、时间轴和唯一主动作 | 编辑、救援、筛选使用 `ModalBottomSheet`；遵循安全区。 |
| `720-1199px` | 88px 紧凑 `NavigationRail` + 标题栏 | 时间地图为主；救援摘要可展开 | Dialog 或侧面展开面板。 |
| `>=1200px` | 260-264px 展开侧栏 + 标题栏 | 最大宽度 1320；时间地图右侧固定救援摘要 | Dialog；允许键盘操作和 Tooltip。 |

当前实现为了兼容既有 Flutter 测试使用约 1024px 的壳层切换点；新页面必须使用 `LayoutBuilder`/约束适配，逐步向本表的 720/1200 语义收敛，不用固定屏幕宽度硬编码布局。

### 3.2 桌面侧栏

展开侧栏宽度 260-264px，背景为 `surface`，右侧 1px `divider`。分组顺序固定：

```text
今天：专注、智能日历
规划：微任务、目标
协作：团队
复盘：周报/月报、日程救援记录
系统：个人、集成、设备、主题/语言
```

保留现有五个一级入口（Focus、Schedule、Micro、Team、Profile）；目标、复盘、集成和设备作为页面内导航或设置入口，不在底栏增加第六项。选中项同时使用指示背景、图标和文字权重表达，不能只靠颜色。

### 3.3 标题栏与手机底栏

- 标题栏：当前页面标题、日期/范围、数据来源状态、搜索或快捷入口、账户/设置入口。
- 手机顶部：日期、能量/恢复状态、远端/本地来源；不放过多并列操作。
- 手机底栏最多 5 项，始终保留文字标签；每个目标区域至少 48dp，并给底部安全区预留内边距。
- 页面切换保持导航位置、筛选、滚动和编辑草稿；返回行为遵循系统后退/侧滑，不覆盖系统手势。

## 4. 页面模式

每个页面只保留一个主动作，其余为次级按钮、菜单或图标操作。页面标题使用 `pageTitle`，工作区区块使用 `sectionTitle`，不使用营销型巨型标题。

| 页面 | 信息层级 | 唯一主动作 | 关键组件与状态 |
| --- | --- | --- | --- |
| **专注 Focus** | “现在做什么” -> 当前任务 -> 接下来四小时 -> 救援/协作 | 开始/暂停当前任务 | `CurrentTaskPanel`、`EnergyStatus`、`MiniTimeline`、`SyncStatus`；计时使用等宽数字，开始/暂停/重置均有反馈。 |
| **智能日历 Schedule** | 日期与视图 -> 今日状态 -> 时间地图 -> 救援摘要 | 添加紧急任务/启动救援 | `SegmentedButton` 日/周/月/甘特、手动/智能模式、字段筛选、`ScheduleTimeline`、`RescueSummary`；先比较三方案，再确认写入。 |
| **微任务 Micro** | 收件箱 -> 筛选/批量选择 -> 时间晶体建议 | 添加微任务 | `ListTile`/批量工具条；推荐来源标注本地或远端，批量操作可撤销。 |
| **团队 Team** | 成员状态 -> 共享权限 -> 忙碌块/共同窗口 -> 团队任务 | 添加团队任务或查看可用窗口 | 不把预留的冲突、黄金窗口、预约接口显示为成功；权限/加载/空数据清晰可见。 |
| **目标 Goals** | 目标进度 -> 依赖树 -> 下一任务 | 新建目标 | 进度树和任务拆解保持可读；安排动作受服务能力和权限状态约束。 |
| **复盘 Review** | 周/月摘要 -> 完成/延期 -> 救援接受/撤销历史 -> 调度参数 | 切换复盘周期 | 周报、月报、历史和调优使用同一状态模型；无数据不是错误。 |
| **个人/集成/设备** | 账户 -> 主题/语言 -> 接入能力 | 保存设置或登录 | 统一设置表面；远端主题/语言、集成和设备预留状态显示“待接入”，不伪造可用。 |
| **登录 Auth** | 账号字段 -> 密码管理 -> 错误/加载 | 登录/注册 | 使用可见标签、粘贴和密码管理器；失败错误贴近字段，支持取消和返回。 |

### 4.1 双层工作台布局

```text
上层：当前任务 + 计时器 | 能量/情绪 | 同步来源 | 唯一主动作
下层：未来四小时 MiniTimeline | RescueSummary | TeamWindowPreview | TodayQueue
```

上层回答“现在做什么”，下层回答“接下来怎么安排”。卡片尺寸按内容确定，不把所有模块做成同样大小的卡片；桌面优先横向扫描，手机按主路径顺序纵向排列。

### 4.2 时间地图与救援方案

- 时间刻度、固定事件、任务块、空档和冲突有稳定几何尺寸；块内至少显示标题、时间/时长和状态，负荷/截止使用辅助信息。
- 任务块颜色必须配合文字、图标、纹理或边框表达状态；键盘用户可聚焦并打开详情。
- 救援界面是三个可比较的候选计划，而不是三段说明文字：标题、适用场景、移动任务数、恢复缓冲、逾期风险、受影响任务和解释码都可见。
- 采用方案前不写入；写入成功显示撤销入口，失败保留原计划并给出重试/修正路径。
- 桌面/平板使用 `Dialog`，手机使用 `ModalBottomSheet`；未保存草稿关闭前要确认，所有弹层有明确关闭/取消出口。

## 5. 组件与状态契约

### 5.1 组合组件

| 组件 | 责任 | 必需输入 | 禁止行为 |
| --- | --- | --- | --- |
| `AppShell` | 响应式壳层、导航和安全区 | 当前路由、导航项、窗口宽度、回调 | 直接访问服务或重置页面状态。 |
| `MacSidebar` | 展开侧栏、分组和选中态 | 导航项、选中项、Tooltip/语义 | 把二级设置伪装成一级底栏。 |
| `WorkspaceTitlebar` | 标题、日期、来源、快捷入口 | 标题、日期、`SyncStatus`、回调 | 用颜色隐藏同步失败。 |
| `CurrentTaskPanel` | 当前任务、计时、完成/暂停 | 任务模型、计时状态、回调 | 在组件内部写数据库或事件。 |
| `MiniTimeline` | 未来四小时节奏概览 | 时间块、当前时间、点击回调 | 依赖精确拖拽才能完成关键操作。 |
| `EnergyStatus` | 能量/情绪数据和建议动作 | 当前分数、样本状态、回调 | 把缺失数据渲染成 0 分或假建议。 |
| `SyncStatus` | 来源和同步队列的统一表达 | `remote/local/offlineQueued` 状态 | 把本地缓存标记为实时远端。 |
| `ScheduleTimeline` | 日/周/月/甘特时间地图 | 视图、事件、筛选、焦点/键盘回调 | 改变服务模型或吞掉冲突。 |
| `RescueSummary` | 当前冲突、最近接受/撤销 | 救援记录、冲突状态、回调 | 把 501/失败显示成成功。 |
| `StatusBanner` | 页面级来源/错误/冲突提示 | 语义状态、文案、重试/关闭回调 | 仅用颜色、自动消失关键错误。 |
| `EmptyState` | 无数据时的原因和下一步 | 标题、说明、主/次动作 | 空白区域或伪造示例数据。 |
| `ActionFeedback` | 成功、撤销、离线队列、失败反馈 | 操作结果、撤销/重试回调 | 静默成功或让 Toast 抢夺焦点。 |
| `GlassSurface` | 局部层级和状态分组 | 子内容、语义角色、主题 | 大面积透明背景、用模糊替代对比度。 |

组件只通过构造参数接收模型、状态和回调；页面控制器负责把服务结果映射为可渲染状态。

### 5.2 统一状态模型

| 状态 | 用户可见表达 | 允许操作与规则 |
| --- | --- | --- |
| `idle` | 默认内容和可用操作 | 主操作可执行。 |
| `loading` | 骨架或局部进度，保留上下文 | 禁用重复提交；预计超过 1 秒使用骨架。 |
| `success` | 成功图标/短消息、更新后的数据 | 必须有简短反馈；不抢夺焦点。 |
| `empty` | “暂无数据”原因 + 下一步动作 | 不等同于请求失败；保留创建入口。 |
| `offline` | “本地模式”来源标签 | 核心日程可继续操作；解释同步限制。 |
| `offlineQueued` | “已保存到本地，待同步” | 显示队列/重试入口，不声称已远端写入。 |
| `validationError` | 字段下方具体错误，必要时顶部摘要 | 保留输入；聚焦第一个错误或错误摘要。 |
| `unauthorized401` | 登录/权限原因和登录入口 | 不清空原内容；支持返回和重新登录。 |
| `conflict409` | 冲突对象、版本/来源和解决动作 | 不覆盖用户数据；允许刷新、比较或取消。 |
| `error422` | 字段或请求格式的修正建议 | 不转换为空列表；保留可编辑上下文。 |
| `reserved501` | “接口待接入”及当前可用替代 | 禁止显示完成、成功、实时或已预约。 |
| `error5xx/timeout` | 原因、重试和本地兜底说明 | 保留原计划和输入；重试按钮靠近错误。 |

状态文案应包含“发生了什么 + 用户能做什么”，错误显示在触发控件附近；危险操作提供确认和 3-5 秒可撤销反馈。

## 6. 交互、动效与表单

### 6.1 操作层级

| 层级 | 控件 | 使用规则 |
| --- | --- | --- |
| Primary | `FilledButton` | 每个页面一个；用于开始/添加/确认等主动作。 |
| Secondary | `OutlinedButton` | 比较、重试、打开筛选等次级动作。 |
| Tertiary | `TextButton`/`Menu` | 取消、查看详情、非破坏性辅助动作。 |
| Icon | `IconButton` | 删除、撤销、更多、关闭等熟悉命令；必须有 Tooltip/语义。 |
| Choice | `SegmentedButton`/`FilterChip` | 日/周/月/甘特、手动/智能和字段筛选。 |

### 6.2 触控与键盘

- iOS 命中区域至少 44pt，Android/Material 至少 48dp；目标之间至少 8dp 间距。
- 点击后 100ms 内出现按下态（ripple、透明度或轻微 elevation），不改变布局边界。
- 不依赖 hover 完成关键流程；拖拽提供上下移动菜单、步进按钮或键盘操作替代。
- 桌面 Tab 顺序与视觉顺序一致，焦点环使用 `focusRing` 且不被 Sticky/弹层遮挡。
- 删除、覆盖、撤销和关闭未保存表单前确认；Toast 使用 polite/live 语义，不抢夺焦点。

### 6.3 动效令牌

| 令牌 | 时长 | 用法 |
| --- | --- | --- |
| `motionPress` | 80-120ms | 按下/释放反馈。 |
| `motionControl` | 180ms | 颜色、透明度、选中态和小位移。 |
| `motionPage` | 260ms | 页面/区块切换，保持空间连续。 |
| `motionReveal` | 280-360ms | 首屏最多 4 组淡入上移，位移 8-16px。 |
| `motionExit` | 160-220ms | 退出比进入更快。 |

只动画透明度、颜色、轻微位移和进度；不动画化宽高、top/left 或持续背景效果。动画必须可打断，`MediaQuery.disableAnimations`/系统 reduced-motion 开启时直接渲染最终状态。

### 6.4 表单与反馈

- 每个输入有可见标签、必要时有持久 helper text；移动端输入高度至少 44px。
- 复杂表单按“必需 -> 约束 -> 可选”渐进披露；失焦后校验，提交后保留字段值。
- 多错误提交显示可聚焦的错误摘要，并链接到字段；错误文案写明原因和修复动作。
- 登录支持密码管理器、粘贴和显示/隐藏密码；不引入认知挑战。
- 批量删除、方案采用和覆盖写入都提供确认；成功后可撤销，失败后可重试。

## 7. 数据来源与接口边界

| 用户操作 | 服务层 | UI 来源/状态 | 远端边界 |
| --- | --- | --- | --- |
| 添加/编辑/删除日程 | `DataService` | 远端成功或本地兜底 | `/schedule` POST/PUT/DELETE。 |
| 重新规划 | `DataService` | 方案草案，确认前不写入 | `/schedule/replan`。 |
| 生成/采用/撤销救援 | `ScheduleRescueService` | 本地流程可用，写入后可撤销 | `/schedule/rescue/*` 服务端已实现（options/apply/undo/history，含基线哈希与撤销快照）；客户端暂沿用本地闭环。 |
| 能量/情绪读取与打卡 | `DataService` | 当前数据、空状态或离线 | `/energy/*`、`/emotion/*`。 |
| 微任务 CRUD/推荐 | `DataService`/本地引擎 | 来源标签为本地或远端 | `/microtasks` 可用；推荐未接入时显示本地来源。 |
| 目标与目标任务 | `DataService` | 进度/依赖/错误状态 | `/goals` 可用；`goals/{id}/schedule-next` 预留。 |
| 团队成员、权限、日历 | `DataService` | 权限、成员、日历来源清晰 | `/team/members`、`/team/calendars`、`/permission`。 |
| 团队冲突/黄金窗口/预约 | 服务适配器 | 待接入、不可操作或本地说明 | `/team/conflicts`、`/team/golden-windows`、`/team/book-meeting` 预留。 |
| 周报/月报/救援历史/调优 | `DataService` | 真实事件与无数据区分 | `/review/*`。 |
| 行为事件 | `logTaskEvent`/`upsertTaskEvents` | 写入结果和重试 | `/events`、`/events/batch`。 |
| 登录/注册/当前用户 | `RemoteDataService` | loading、401、成功 | `/auth/login`、`/auth/register`、`/auth/me`。 |
| 主题/语言 | 本地 `DataService` | 本地持久化 | 远端方法当前不可用。 |
| 集成/设备/AI | 现有适配边界 | 待接入/预留 | `/integrations/*`、`/devices/*`、`/ai/*`。 |

任何 4xx、鉴权失败、冲突、响应格式错误和 501 都必须保留错误语义；不能转成空列表、默认成功或“已同步”。

## 8. 可访问性、性能与视觉 QA

### 8.1 可访问性底线

- 浅色/深色主文字和正文对比度 ≥4.5:1；焦点环和非文本控件边界 ≥3:1。
- 图标按钮有语义名称、Tooltip 和状态；装饰图标从辅助技术树隐藏。
- 颜色之外同时使用文字、图标、边框或纹理；时间地图提供可读的列表/详情替代。
- 支持键盘导航、系统后退、动态文字大小、屏幕阅读顺序、reduced-motion 和安全区。
- Sticky 标题栏、底栏、Toast、Dialog/BottomSheet 不得遮挡焦点；关闭、取消和返回始终可见。

### 8.2 响应式与性能验收尺寸

至少检查：`375x812`、`390x844`、`720x900`、`1024x768`、`1440x900`，并覆盖手机竖屏、平板横屏和桌面窗口调整。

- 手机无横向滚动；长标题、标签集合和错误文案允许换行或通过 `+n` 展开，不压缩到不可读。
- 异步区域预留空间，超过 1 秒用骨架；列表 50+ 项考虑虚拟化，避免频繁布局读写。
- 首屏不运行持续动画；时间轴、图表和计时更新保持主线程帧预算。
- 确认深色模式、系统字体放大、禁用动画和离线网络四种组合状态。

### 8.3 交付前命令

```text
flutter analyze
flutter test
dart format --set-exit-if-changed .
git diff --check
```

截图/浏览器验收必须记录真实尺寸、数据来源、控制台错误和已知未覆盖项；通过本地测试不等于硬件、远端或生产环境已验收。

## 9. 实施清单与变更规则

- 令牌入口：`lib/theme/app_theme.dart`；组件只能引用语义色、字体、间距和圆角令牌。
- 壳层入口：`lib/screens/main_screen.dart`；五个一级导航保持不变，响应式使用约束布局。
- 首页核心：`focus_page.dart`、`focus_task_card.dart`、`energy_status_card.dart`、`mini_timeline.dart`、`workspace_status_bar.dart`。
- 日历/救援核心：`smart_calendar_page.dart`、`schedule` 服务和 `rescue_summary.dart`；不改变确认、持久化、撤销和事件记录闭环。
- 任何新页面先补 loading/empty/offline/401/409/422/501/undo 的状态映射，再补视觉细节。
- 新增组件不得直接访问网络、数据库或全局单例；接口模型不一致时停止并报告，不猜字段。
- 新的页面视觉若与本文冲突，必须先更新本文的令牌、页面模式或边界，再实现代码；不得在单页添加未经评审的渐变、光球、无限圆角或第二套状态语言。

### 明确非目标

- 不制作营销落地页、Hero 视频、装饰性背景动画或复杂 3D/玻璃效果。
- 不新增第三方 UI 框架，不重写 FastAPI/SQLite/DataService，不复制竞品专有算法。
- 不把本地预览数据、模拟硬件、预留接口或未接入 AI 标记为实时生产能力。
