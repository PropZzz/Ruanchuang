## 0. 一句话结论

**产品主链路已经闭环、可以演示、线上也在运行，但工程已经从"功能开发期"进入"收口期"——
现在缺的不是新功能，而是把三个月积累的三套前端、两套调度实现、一批过期文档和一组生产安全隐患收敛成一条可信基线。**

具体说：核心闭环（紧急任务 → 三方案比较 → 确认写入 → 撤销 → 事件复盘）在 Flutter 客户端和 Web 端都已接通真实后端；
线上 `http://8.133.250.216` 可用，66 个后端端点在线；后端 209 项测试实测 208 通过。
但有四个硬伤必须先处理：**双前端分叉、Dart/Python 调度对拍未清零、认证是进程内 token、无 TLS。**

## 3. 已完成能力地图

### 3.1 后端（可信度最高的一层）

- **认证与用户**：注册 / 登录 / `me` / 登出 / 改资料，Bearer token + 用户隔离
- **日程**：CRUD、`/replan` 重排、`/batch` 批量写、`/conflicts`、`/import-ics`、`/export-ics`
- **救援事务（核心亮点）**：`options` / `apply` / `undo` / `history`，基线哈希校验 + 单 SQLite 事务 + 撤销快照，失败全回滚
- **事件**：单条 / 批量幂等写（拒绝空 ID、批内重复、跨用户 ID 冲突）
- **微任务**：CRUD、推荐、批量完成、批量排程、文本导入
- **目标**：目标与子任务 CRUD、`schedule-next`
- **团队**：成员 / 权限 / 日历、冲突检测、黄金窗口、会议预订
- **复盘**：周报 / 月报 / 救援历史 / 调优读写
- **其他**：情绪、能量、设置（按用户持久化）、同步 `/sync/*`、诊断摘要、版本、服务器时间

66 个端点全部有对应 pytest 覆盖，是本项目质量最扎实的部分。

### 3.2 Flutter 客户端

- 响应式壳层（手机五项底栏 / 平板 Rail / 桌面侧栏）、主题令牌、GlassSurface
- 专注页：当前任务、计时、能量、微时间线
- 智能日历：日/月/甘特、增删改、重复规则、提醒、冲突
- 微任务：CRUD、批量导入、碎片时间推荐、优先级解析

## 4. 关键问题清单（按严重度）

### 🔴 P0-1 双前端分叉：Flutter Web 已被废弃，但 Flutter 客户端还在长

证据：`d58aea2 chore: make Stitch the only web entry` 之后，Web 入口只跑 Stitch HTML；
但 `lib/` 下 34,000 行 Flutter 仍在维护，Android/iOS 还依赖它。

后果：同一个业务要改两遍（一份 Dart、一份 HTML+JS），且两边功能已经开始不一致
（例如 Flutter 的救援已接远端，Stitch 走 `rescue-options`，但页面状态机不同源）。
另外 `router.js` 里靠**中文按钮文案**匹配动作（`label.includes('新增日程')`、`'保存并写入日程'`），
改一个文案就会静默失效，且没有编译期保护。

### 🔴 P0-2 Dart / Python 调度结果不一致，性能基准被门禁锁死

证据：`reports/shared-vector-diff.md`（2026-09-16）——12 个场景中 **mismatched 9**
（3 个 allowed_difference、3 个 contract_error、6 个 implementation_error，共 65 条差异）。
`README.md` 明确写了：`mismatched≠0` 时 benchmark 输出 `status=blocked`、退出码 2，**不产生任何性能结论**。

后果：本地兜底算出的排期和服务器算出的排期可能不同，用户切换网络状态会看到不同结果。
好处是：这套对拍机制本身是本项目最专业的部分，只是没跑完。

### 🟠 P0-3 认证是进程内 token，重启即全体掉线

证据：`backend/auth.py` 用模块级字典 `_TOKEN_TO_USER_ID` 存在内存里；`main.py` 里 `allow_origins=["*"]`。

后果：uvicorn 一重启所有用户被登出；一旦起第二个 worker，token 立刻失效；无法横向扩容。
这是"能演示"和"能上线"之间的分水岭。

### 🟠 P0-4 无 TLS，只有 IP 直连

证据：`deploy/nginx-ruanchuang.conf` 只有 `listen 80`，`deploy/README.md` 写着"绑定正式域名后再配置 TLS"。

后果：Bearer token 明文传输；浏览器会标"不安全"；无法接入需要 HTTPS 的第三方能力。

### 🟡 P1-1 三个月的文档数字已经过期

`功能核对与启动说明.md` 写"Flutter 177 项通过、后端 59 项通过"；
实测后端已是 **209 项**，Flutter 测试文件已是 **53 个**。
`五人开发分工文档.md` 里"ahead 13 / 工作树大量未提交"也早已不成立（现在是干净的 `0 0`）。
文档是团队协作的契约，数字过期会让新成员误判。

### 🟡 P1-2 一个 8 提交的分支悬空未决

`origin/codex/member-d-client-identity-isolation`（2026-09-24，+2,425 行）尚未合并，
内容是客户端身份隔离与登出清 token。而 `main` 上后来已经有了 `accountScope` 方案，
两者关系未写明——**是要合并、要挑拣、还是直接废弃，必须有人拍板**，否则会误导后来者重做。

### 🟡 P1-3 视觉基线快照没进版本库

`test/failures/` 下 6 个 PNG 处于 untracked 状态，是 9 月 26 日视觉回归的差异图。
要么清理，要么纳入 `test/goldens/` 并说明差异原因，不能一直挂在 `git status` 里。

### 🟢 P2 其他

- 后端 1 项测试有跨用例污染（单独跑通过、全量跑失败），属测试隔离缺陷
- 页面文件过大（日历 3,140 行），新人上手成本高
- 33 个依赖有新版本不兼容（`flutter pub outdated`），暂不影响运行

### 阶段一：基线收口（约 2 天，1 人）

| 任务 | 动作 | 验收标准 |
| --- | --- | --- |
| 1.1 复跑三件套 | 在本机终端跑 `flutter analyze`、`flutter test -r compact`、`pytest backend/tests -q`，把输出贴进 `功能核对与启动说明.md` | 三项有真实输出和时间戳；Flutter 测试必须真跑一次 |
