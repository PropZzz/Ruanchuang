# 真实日期与账号日程实施计划

**目标：** 智能日历按真实本地日期展示当前账号日程，支持日/周/月、翻页、今天及日期选择；增删改后刷新并保留当前视域与抽屉动效。

**方案：** 保留原桌面/手机页面布局、字体、颜色、公共导航和抽屉；恢复旧模板，通过局部节点填充接入真实数据。在独立 `web/stitch/calendar.js` 实现日期模型、重叠布局、重复日程展开与视图控制器；通过现有鉴权 `/schedule` 集合接口获取实际数据。桌面日/周使用原时间地图，手机日/周沿用日期胶囊与纵向任务列表；月视图在原日历区域内显示日期格。加载、空、登录、失败均明确反馈，不展示示例任务。

**技术：** 原生 JS/DOM/CSS、FastAPI 既有接口、Node test 与 Playwright。

1. [x] 新增 `tools/tests/stitch_calendar.test.mjs`：本地日期、周一边界、闰年/跨年、月末翻页、重复截止日、跨午夜、重叠布局；先运行失败，再实现纯函数。
2. [x] `web/stitch/calendar.js` 与 `web/stitch/assets/calendar.css`：日期导航、日/周/月渲染、当前时间线、账号数据加载/重试、点击真实 id 打开详情、选定日期新建。
3. [x] 恢复桌面/手机 schedule 原模板结构和视觉，局部移除静态示例，保留控制台、指标、时间地图、救援区域及导航；`router.js` 安装控制器并刷新真实数据、接通保存删除通知；为 create-schedule 表单提供可编辑日期/时间/时长。
4. [x] 入口与构建版本化新脚本；检查资源引用。浏览器验证桌面/手机导航、CRUD、账号切换、错误/空态与抽屉回归；截图一次集中检查，修复后至多再确认一次。
5. [x] 独立代码审查，修复重要问题。原子部署服务器，核对 release/health 并对线上静态产物运行使用 fixture API 的浏览器检查，记录结果。

约束：日期按浏览器本地日历日计算，避免 UTC 导致前后偏移；周从周一开始。重复日程展开仅用于展示，编辑/删除操作作用于原始记录，界面说明此语义。保留 Flutter 和后端契约。账号切换清除视图数据，旧响应不得覆盖新账号或新视域。

补充约束（用户确认）：外观尽量不要发生变化。禁止用新标题、工具栏或独立日程侧栏替换原页面；DOM 保留检查和桌面/手机截图共同验证。
