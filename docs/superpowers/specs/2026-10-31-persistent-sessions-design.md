# 持久化认证与生产准备

依据已确认的收口计划，认证采用 SQLite 不透明会话表。继续使用现有随机 Bearer token 和 REST 响应；存储 SHA-256 token 摘要、用户 ID、创建时间和到期时间。相比 JWT，本阶段无需引入签名密钥和额外吊销机制，可以直接沿用现有 SQLite 用户与备份边界。

`SessionStore` 是独立数据库模块；FastAPI 依赖和认证路由传入应用实际数据库路径。会话按数据库隔离，重启后可验证，退出即删除，过期无效；默认有效期 7 天，通过 `SHIXUZHIPEI_SESSION_TTL_SECONDS` 配置。原进程内令牌不迁移，首次切换此实现后需要重新登录。

CORS 使用 `SHIXUZHIPEI_CORS_ORIGINS` 的显式 HTTP(S) origin 列表，默认包括现有服务器 IP 和两个 5353 本地预览 origin。禁止通配值、带凭据或带路径的 URL；非法配置在启动时失败。其他端口和未来 HTTPS 域名需要明确加入。

备份/恢复使用 SQLite backup API，覆盖 WAL 中已提交数据；以完整性与用户/日程/会话计数校验恢复，先保存现有数据库备份。自动化工具和部署模板在本地验证，现有服务器的版本、路径及认证信息须据实核对。

用户已回复暂无正式域名。域名、证书签发和 HTTPS 上线保持待配置；当前阶段完成模板及运维说明。

验收覆盖：跨应用/进程验证、数据库隔离、到期、吊销、无明文 token 落库、CORS 成功/拒绝、备份恢复后重新读取会话与业务数据。测试均使用隔离数据库，不依赖进程内全局 token 重置。
