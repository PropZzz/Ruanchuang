# 前后端功能对齐与二级页面退出设计

## 目标

让 Web 前端每个可操作入口都有真实、可见的行为，并使已有 FastAPI 能力经由 Flutter 数据服务实际可达；无法由当前本地代码真实提供的设备、通知和第三方集成功能保持明确的未接入状态。用户在任意二级页面都能通过可见返回控件或系统/浏览器返回回到主应用。

## 当前证据

- `CompositeDataService` 默认本地优先读取，远端写成功后又尽力同步本地；当缓存较旧时，页面可能继续显示旧状态。
- `RemoteDataService` 的主题、语言、收藏设备和专注任务方法未实现；后端已有的目标排程、月报、微任务批处理/推荐、日程冲突与 ICS、救援和团队分析能力有部分未进入统一数据服务契约。
- 多个页面通过 `Navigator.push(MainScreen(secondaryPage: ...))` 创建二级壳；关闭依赖切换主导航，缺少一致的应用栏返回及 PopScope 行为。
- 公网 `/health` 返回 200；公网 `/openapi.json` 返回 SPA HTML，Nginx 当前未代理该路径，线上 API 契约不能通过 OpenAPI 直接核验。

## 设计

1. 以可见按钮为入口逐项建立页面操作到 `DataService`、`RemoteDataService`、FastAPI 路由的映射。已有真实后端端点通过统一数据服务接通，避免页面绕过数据门面或只落入本地状态。
2. 已存在的本地能力而服务端没有持久化模型的功能继续支持本地/离线运行；真正依赖未接入设备、推送或第三方供应商的动作显示清楚的未连接/未提供反馈，不制造成功状态。
3. 远端读取默认优先，只有网络不可用或服务端 5xx 才使用本地兜底；4xx、冲突和响应契约错误原样传递。远端成功后本地缓存失败不得把成功操作报告为失败。
4. 二级页面壳提供可见返回按钮。系统返回和 Flutter Web 浏览器返回先退出二级层，再按 Navigator 当前路由正常返回；切换主导航也立即退出二级层。
5. 使用 Flutter 单元/组件测试和 FastAPI 测试覆盖关键端点映射、远端优先/兜底条件及返回行为；本地 release Web 构建只作为验证，不直接发布到生产机器。

## 验收标准

- 页面中确认可用的操作都能触发本地业务能力或其对应后端请求；未接入外部能力有明确原因和可退出反馈。
- 已登录远端读取返回服务端事实；离线/5xx 时仍可用本地数据，4xx 不被降级吞掉。
- 二级页的关闭按钮、主导航切换和系统/浏览器返回均能离开二级页，且主页面状态可继续使用。
- `flutter analyze`、相关 Flutter 测试、`flutter test -r compact`、`python -m pytest backend/tests -q` 和 release Web 构建通过。
