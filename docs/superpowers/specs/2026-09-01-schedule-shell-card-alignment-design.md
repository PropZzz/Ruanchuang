# 导航、日程与卡片对齐改造设计

## 1. 背景与目标

当前 Flutter 客户端已经具备响应式壳层、Material 3 主题令牌、日历四种视图以及本地优先的数据服务。本轮只优化界面几何、浏览空间和导航交互：

1. 桌面导航默认以窄栏仅图标呈现，可点击展开文字，且窄栏宽度比当前实现更紧凑。
2. 智能日程的详细时间地图获得更大的可用空间，任务块改为更清晰、可读、可对齐的时间轴呈现。
3. 各页面的重复卡片使用统一内容宽度、列宽、间距和行高约束，解决宽屏全屏后的错位与空旷感。

不改变 FastAPI、SQLite、`DataService`/`CompositeDataService`、调度/救援算法、ICS 导入导出、事件记录、本地优先策略或既有路由。

## 2. 组件库检索与取舍

2026-09-01 检索了 Flutter 日历组件：

- `syncfusion_flutter_calendar` 提供完整的日、周、月、日程和时间线视图，但为商业包，需要 Syncfusion 商业或社区授权。
- `table_calendar` 为 Apache-2.0，适合月/双周/周日期网格，不提供当前按小时的时间地图。
- `kalender` 为 MIT，支持 Day/Multi-day/Month/Schedule、拖拽、缩放和自定义事件，但当前仍在 1.0 之前开发阶段，小版本可能存在破坏性 API 变化。

本轮采用自有组合组件 `ScheduleTimeline`。它借鉴成熟日历组件的时间刻度、事件层级和可读性模式，但不引入第三方依赖，也不迫使现有重复规则、ICS 字段和救援写入适配到另一套事件模型。未来若授权和稳定性确认，可以在该组件边界内替换实现。

## 3. 设计方案

### 3.1 桌面导航壳层

- `MainScreen` 增加只属于壳层的 `_railExpanded` 状态，默认 `false`。
- 桌面壳层仍从现有宽屏断点进入；窄栏宽度为 `76dp`，展开宽度为 `248dp`。
- 侧栏顶部提供带 Tooltip 和语义标签的切换按钮。窄栏显示“展开导航”，展开后显示“收起导航”。
- 窄栏始终仅显示图标，展开后显示完整导航标签；选中态在窄栏使用图标和浅色指示背景表达，展开后再叠加文字字重。
- 切换只改变侧栏宽度与标签可见性，不重建 `IndexedStack`，不改变当前页面、滚动位置或页面内部状态。
- 手机 `NavigationBar` 保持现有五项入口和安全区行为；不新增一级导航项。
- 内容区统一使用最大宽度约束，侧栏和内容区共用分隔线令牌。

### 3.2 智能日程展示组件

新增 `lib/widgets/schedule_timeline.dart`，组件接收：

- 事件列表、当前日期、视图模式、可见字段和状态映射；
- 事件选择、删除、日期跳转等回调；
- 时间轴起止小时和主题样式。

组件不访问服务、不写入数据，也不计算救援方案。页面仍负责加载、筛选、模式切换、状态映射、救援确认/撤销、ICS 和错误处理。

页面结构调整为“紧凑状态条 + 宽工具栏 + 主时间地图”。桌面/平板内容最大宽度约 1440px，手机保持纵向滚动；救援摘要和状态信息靠近工具栏分组，减少对详细日程高度的挤压。

日视图使用固定时间刻度和可滚动主轨道，小时行高保持稳定，轨道设置最小可读宽度。任务块使用浅色语义底、左侧强调线、标题、时间、标签和状态信息，不再使用大面积高饱和填充。删除入口保留至少 44dp 命中区域。

周视图使用等宽日期列，列头与时间轴对齐；月视图保留日期网格但统一格高、间距和事件摘要；甘特视图复用相同事件卡片令牌。现有日/周/月/甘特切换、日期翻页、手动/智能模式、字段筛选和所有业务回调保持不变。

### 3.3 全局卡片与宽屏对齐

新增 `ResponsivePageFrame`，统一一级页面的最大内容宽度约 1320px、水平内边距（手机 16、平板 24、桌面 32）和居中对齐。

新增 `ResponsiveCardGrid`：

- 桌面/平板使用两列等宽布局，手机自动单列；
- 同一行的卡片采用拉伸约束，统一顶部、底部和列间距；
- 不强制所有卡片使用固定高度，内容较多的卡片决定该行高度；
- 长列表和时间轴保持全宽滚动，只统一外层起止线和内边距。

专注、微任务、团队、个人设置以及日历状态/救援区块逐步接入该网格。统一几何尺寸，不改文案、服务状态、权限或业务按钮。

## 4. 数据流与错误边界

页面继续通过 `AppServices.dataService` 获取和保存数据。新组件只渲染页面传入的状态：加载、空数据、本地模式、远端成功、冲突、失败和预留能力均沿用现有文案与回调。任何日历组件替换都不得把本地缓存标记为实时远端，也不得把 501/失败渲染为成功。

## 5. 可访问性与响应式要求

- 导航切换、删除、日期翻页和事件入口提供 Tooltip 或语义标签；
- 所有可交互控件命中区域至少 44dp，键盘焦点可见；
- 375、768、1024、1440 宽度下无横向溢出，手机底栏不遮挡内容；
- 浅色/深色主题继续使用现有语义令牌和对比度规则；
- 尊重 `MediaQuery.disableAnimations`，视图切换不通过改变布局尺寸制造抖动。

## 6. 验收与测试

1. `main_screen_shell_test.dart` 验证桌面默认窄栏、展开/收起、导航选择和移动端底栏。
2. `smart_calendar_visual_test.dart` 验证新时间轴语义区域、视图切换和现有救援入口仍存在。
3. 新增 `schedule_timeline_test.dart` 验证日程块、状态字段、删除回调、最小轨道宽度和空数据状态。
4. 新增或扩展响应式测试，覆盖 375、768、1024、1440 宽度，检查无异常与无横向溢出。
5. 运行 `flutter analyze`、目标 Flutter 测试、全量 Flutter 测试和 `git diff --check`。

## 7. 非目标

- 不引入第三方 UI 框架或商业日历依赖。
- 不改后端路由、数据库结构、调度算法、救援事务、ICS 协议或模型字段。
- 不增加目标、复盘、团队高级接口等一级导航入口。
- 不把视觉改造描述为硬件、实时同步或自动决策能力。
