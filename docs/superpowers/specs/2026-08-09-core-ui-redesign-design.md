# 时序智配核心体验重构设计

日期：2026-08-09

## 目标

将现有 Flutter 应用重构为冷静、可信、可快速扫描的调度工作台。用户在突发任务、会议延期或精力下降时，应能清楚地理解日程影响、比较重排方案，并保留最终选择权。

本次重构覆盖：应用壳、视觉令牌、专注页、智能日程、日程救援、微任务、团队页和个人中心/复盘的视觉层级与响应式布局。

## 非目标

- 不改变调度、救援、提醒、存储、认证或远程 API 的业务语义。
- 不迁移技术栈，不引入新的状态管理方案。
- 不删除既有功能入口；低频入口在个人中心的二级菜单中保持可达。

### 组件规则

- 使用 6px 或 8px 圆角、1px 低对比度边框、极轻投影；不使用渐变、毛玻璃或装饰性光晕。
- 页面使用 8px 间距基线，桌面内容最大宽度为 1440px。
- 主操作使用填充按钮；次操作使用描边或纯文本按钮；不可逆操作使用风险色与二次确认。
- 所有状态同时依赖颜色、图标和文字，不只靠颜色表达意义。

## 信息架构与应用壳

一级导航保持：专注、智能日程、微任务、团队、我的。

桌面端在 1024px 及以上显示 240px 左侧导航栏，顶部为品牌与主导航，底部显示用户入口、通知和设置。主区顶部只保留当前页面标题、上下文工具与用户状态。移动端在 1024px 以下使用底部五项导航，并将低频操作折叠进页面工具栏或更多菜单。

个人中心提供二级入口：个人资料、情绪、目标、复盘、设备、集成和诊断。此安排保留现有功能，同时避免主导航过载。

## 页面设计

### 专注

桌面端为 7:5 双栏：左栏依次为精力状态条、当前任务与计时控制，右栏为后续待办和时间晶体建议。当前任务是最高优先级元素，完成、暂停、继续等动作紧邻计时显示。移动端按相同优先级纵向排列。

### 智能日程

日程页以周视图为主，日/月/甘特作为辅助切换。顶栏包含日期范围、手动/智能分段控件、添加日程、插入紧急任务和重新规划。日程主画布显示时间轴与任务块；桌面端右侧是筛选、冲突与当天概要，移动端收为可展开面板。任务块按深度工作、会议、微任务、恢复时间和紧急任务使用语义色与图标。

### 日程救援

插入紧急任务使用紧凑侧栏或移动端底部表单，录入名称、截止时间、时长、优先级和认知负荷。生成候选方案后，使用独立的全屏比较面板：桌面端三列并列，移动端纵向堆叠。每张方案固定展示理由、代价、移动任务数、恢复缓冲、受影响任务和问题数。推荐方案可突出，但不得自动采用。确认后回到日程页并显示持久的撤销状态条。

### 微任务

顶部为标签、时长和状态筛选；批量选择与批量安排只在有选择时出现。任务主体使用紧凑列表行，显示标题、预计分钟数、优先级、标签和操作菜单。碎片时间推荐显示可用时段与一键插入动作。

### 团队

团队推荐以共同空闲时间轴为主，突出黄金协作窗口、忙碌重叠和冲突原因。成员清单及权限设置置于详情区；会议预约从推荐窗口直接发起。

### 我的与复盘

个人资料页显示账户与快捷入口。复盘页优先显示完成率、计划/实际时长、延期归因、救援接受/撤销历史及可执行建议。图表保持简单，数据不足时明确显示空状态而非零值图表。

## 状态与反馈

每个模块应具备加载、空、失败、成功、禁用和撤销状态。失败提示需说明原因与下一步操作；保存、采用救援方案等成功状态显示可撤销动作。删除与风险操作保持二次确认。所有文本在窄屏与大字号下可换行，不截断关键动作。

## 实施边界

优先引入共享的设计令牌与可复用表面、状态标签、页面标题、工具栏、空状态、决策指标组件。随后重构应用壳和五个主页面，保留现有服务与数据模型调用。紧急任务与三方案比较属于重点流程，需覆盖交互与视觉回归检查。

## 验收标准

- 桌面 1440px 与移动 390px 均能完整访问五个主模块，文本和操作不重叠。
- 智能日程的紧急任务录入、三方案比较、采用和撤销入口清晰可见。
- 现有页面的数据加载、添加、编辑、完成、重排、导入导出和导航逻辑未回退。
- `flutter analyze` 与现有测试套件通过；为共享 UI 与关键救援呈现补充针对性组件或页面测试。
