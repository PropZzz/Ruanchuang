# UI 技术审计问题修复设计

## 目标

落实 2026-09-25 对 Flutter 自适应应用的五项审计发现：补齐屏幕阅读器信息、提升日历关键信息可读性、保持致命错误弹窗的主题一致性、提供符合 iOS 习惯的窄屏导航，并降低重复背景模糊带来的渲染开销。

## 设计

1. 为缺少提示的交互图标按钮添加本地化 `tooltip`，让 TalkBack 和 VoiceOver 能识别刷新、切换日期、删除等操作。
2. 将日历中承载任务标题、摘要和时长的微小字号提升至至少 12sp；时间轴装饰刻度可维持紧凑，但必须仍可随系统字号放大且不裁切。
3. 致命错误 `AlertDialog` 使用当前 `ColorScheme` 的背景、正文和操作颜色，不固定浅色值；弹窗文案与现有行为不变。
4. 窄屏主导航按平台分流：iOS 使用 Cupertino 风格的标签栏，Android 继续使用 Material 3 `NavigationBar`；宽屏导航轨道不变。五个目的地与当前选中状态保持一致。
5. 玻璃表面仅让结构性浮层保留模糊，重复内容卡片使用不透明语义表面；调低剩余模糊强度。高对比度模式继续禁用模糊。性能改善通过源码和 widget 测试验证，真实设备帧率不作未经测量的承诺。

## 验收

- 针对无提示按钮、日历字号和主题错误弹窗增加回归测试，测试应覆盖语义标签、字号缩放以及暗色主题颜色。
- 导航测试验证 iOS 使用 Cupertino 标签栏、Android 使用 Material 导航栏，并验证选中索引行为。
- 玻璃表面测试验证内容层不再创建背景滤镜、结构浮层仍可模糊，且高对比度设置会关闭模糊。
- `flutter analyze` 与相关 widget 测试通过；不修改或清理工作区中已有的未跟踪截图。

## 非目标

- 不重构主导航状态管理，不改动五个目的地的名称和顺序。
- 不全面重做 iOS 页面样式，不改变日历数据密度或现有文案。
- 不删除用户已有的工作区文件，也不通过模拟器截图替代真实设备性能测量。
