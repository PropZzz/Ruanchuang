# 三种救援策略规则设计

> **状态：** 待实现
> **负责人：** 成员 A
> **范围：** 救援策略契约、纯调度规则、评分与解释码

## 目标

把“优先保住截止时间”“优先保留恢复时间”“尽量少动原计划”从界面标签变成可重复执行、可跨 Python/Dart 验证的策略规则。三种策略共享同一个约束阶段和候选时间块计算器，只在硬约束通过后改变软目标与候选选择偏好。

本设计不改变救援采用/撤销事务、基线哈希、快照或事件字段；`score`、`scoreBreakdown` 和规则诊断字段均为兼容性增量。

## 统一调度顺序

每个策略都按以下顺序处理请求，不允许用软分数替代前面的失败：

1. 规范化日期、分钟和任务 ID；拒绝无效窗口，窗口结束必须晚于开始。
2. 锁定所有 `fixed` 条目。固定条目既不能移动也不能被普通任务覆盖；固定条目越出工作窗口或彼此重叠时生成 `fixed_conflict` 诊断，仍原样保留。
3. 从提供的工作窗口扣除固定条目，得到合法候选空档。没有提供窗口时不虚构 08:00-20:00 空档，任务只能产生 `no_slot`。
4. 只对依赖已放置的任务尝试安排；未知、失败或循环依赖产生 `dependency_blocked`，并返回 `blockedBy`，不生成计划条目。
5. 应用 `earliestStart` 和截止时间。`hardDeadline=true` 的任务只能安排在截止时间之前；软截止没有可行的准时空档时可以使用最早合法空档，但必须生成 `miss_due`。请求日早于任务截止日的任务不计入当日截止风险；请求日晚于截止日时生成 `overdue`。
6. 仅在以上硬约束通过后，对可行候选计算能量、紧急度、优先级、基线稳定性和恢复偏好的软分数。
7. 推荐方案按硬问题数升序、软总分降序、固定策略顺序升序选择。任何硬问题数较多的方案都不能因软分较高而胜出。

`fixed_conflict` 是固定日程诊断，不会改变固定条目的内容；`no_slot`、`dependency_blocked` 和硬截止失败属于硬问题。硬问题计数必须在 Python 与 Dart 相同。

## 策略规则矩阵

### 优先保住截止时间 (`protectDeadline`)

- **适用场景：** 有一个或多个临近截止的紧急任务，用户首先要降低逾期概率。
- **固定日程：** 不允许移动、缩短或覆盖 `fixed` 条目。
- **普通基线条目：** 允许在合法空档内重排；只要不违反固定日程、窗口、依赖和硬截止，可以移动多个条目。
- **截止处理：** 紧急任务和其他带截止任务按同日截止时间升序优先；硬截止没有迟到回退，软截止的迟到只作为 `miss_due` 风险。
- **低精力匹配：** 低负荷任务获得能量匹配分；高负荷任务不会因能量分数而越过紧急度或硬约束排序，只在可行候选中降低偏好。
- **移动数量：** 对比目标日基线中具有稳定 ID 的条目；条目缺失、开始时间变化或时长变化超过 0.1 分钟各计 1 次，新增紧急任务和恢复块不计入。
- **恢复缓冲：** 不主动插入恢复块，实际恢复分钟数为 0。
- **逾期风险：** `missedDeadlineCount / max(1, dueTaskCount)`，其中 `missedDeadlineCount` 包含 `miss_due` 和 `overdue`；风险越低，`urgency = 1 - risk` 越高。
- **权重与优先级：** `urgency=0.55`、`priority=0.25`、`energyFit=0.10`、`stability=0.10`、`recovery=0.00`；硬约束优先于全部权重。
- **解释码：** 按 `deadline_proximity`、`priority`、`energy_fit`、`kept_baseline`、`fixed_conflict` 的顺序生成并去重。紧急或带截止任务安排依据为 `deadline_proximity`；优先级决定位置时加入 `priority`；低负荷与当前能量匹配时加入 `energy_fit`；未移动基线条目加入 `kept_baseline`；固定日程导致候选受限时加入 `fixed_conflict`。

### 优先保留恢复时间 (`protectRecovery`)

- **适用场景：** 用户处于低能量、连续被打断或需要避免任务堆叠，希望保留可执行的恢复空间。
- **固定日程：** 不允许移动、缩短或覆盖 `fixed` 条目。
- **普通基线条目：** 允许在合法空档内重排，优先保留不动的条目；若恢复块没有合法位置，不能越出窗口或覆盖固定条目。
- **截止处理：** 仍先满足硬截止；软截止可迟到并生成 `miss_due`，不能用恢复偏好掩盖硬截止失败。
- **低精力匹配：** 将目标能量降低一档（最低为 `veryLow`），在可行候选中优先 `low`/`medium` 负荷，降低高负荷任务的匹配分；这不会改变依赖、窗口或硬截止结果。
- **移动数量：** 使用与其他策略相同的稳定 ID、时间和时长比较公式；新增恢复块不计入移动数。
- **恢复缓冲：** 目标为 15 分钟。只在工作窗口内、扣除固定和已选任务后找到连续 15 分钟空档时插入恢复块；`recoveryMinutes` 等于实际插入分钟数，找不到时为 0 并保留可行任务结果。
- **逾期风险：** 与其他策略使用同一 `missedDeadlineCount / max(1, dueTaskCount)` 公式，不因恢复缓冲而降低风险统计。
- **权重与优先级：** `urgency=0.20`、`priority=0.10`、`energyFit=0.35`、`stability=0.10`、`recovery=0.25`；硬约束优先于全部权重。
- **解释码：** 使用同一稳定顺序；恢复块实际插入且任务负荷与降低后的能量匹配时加入 `energy_fit`，保持的基线条目加入 `kept_baseline`，固定日程限制候选时加入 `fixed_conflict`。恢复块不使用无法验证的自由文本码。

### 尽量少动原计划 (`minimizeChanges`)

- **适用场景：** 原计划大部分仍可执行，只需在不破坏既有安排的前提下塞入一个紧急任务。
- **固定日程：** `fixed` 与目标日全部基线条目都锁定，不允许移动、缩短或覆盖。
- **普通基线条目：** 视同固定条目；只为紧急任务寻找剩余合法空档，不重排或删除基线任务。
- **截止处理：** 紧急任务必须先尝试硬截止内的合法空档；无空档时产生 `no_slot`/硬截止问题，不能移动基线任务换取更高分。软截止迟到只生成 `miss_due`。
- **低精力匹配：** 仅作为紧急任务候选空档的软分；不能改变基线锁定，也不能越过截止和依赖约束。
- **移动数量：** 因基线全部锁定，合法方案为 0；若候选结果缺少或改变基线 ID，则每个受影响条目按统一公式计数，并产生对应硬问题/诊断。
- **恢复缓冲：** 不主动插入恢复块，实际恢复分钟数为 0。
- **逾期风险：** 使用同一截止风险公式；基线锁定造成的紧急任务迟到计入 `miss_due` 或 `overdue`，不得被稳定性高分抵消。
- **权重与优先级：** `urgency=0.25`、`priority=0.15`、`energyFit=0.05`、`stability=0.55`、`recovery=0.00`；硬约束优先于全部权重。
- **解释码：** 保持不动的基线条目加入 `kept_baseline`；紧急任务有截止时加入 `deadline_proximity`，按优先级选槽时加入 `priority`，能量匹配时加入 `energy_fit`；锁定基线造成候选受限时加入 `fixed_conflict`。

## 可验证指标

所有指标先限制到 `[0, 1]`，再按策略权重相加并四舍五入到 6 位：

```text
overdueRisk = missedDeadlineCount / max(1, dueTaskCount)
urgency     = 1 - overdueRisk
priority    = placedPrioritySum / (5 * max(1, taskCount))
energyFit   = 1 - weightedLoadMismatch / max(1, placedTaskCount)
stability   = 1 - movedEntryCount / max(1, baselineEntryCount)
recovery    = min(recoveryMinutes / recoveryBufferMinutes, 1)
score       = Σ(metric × strategyWeight)
```

`weightedLoadMismatch` 将负荷等级映射为 `low=0`、`medium=1`、`high=2`，与目标能量等级的距离除以 2；分片任务按原任务 ID 聚合，不能因为 `id#1` 等分片 ID 而从已放置任务中消失。`overdueRisk` 作为诊断值返回；现有 `urgency` 字段保持兼容并等于 `1 - overdueRisk`。

## 解释码生成

解释码来自可观察事实，不来自模型生成文本。每个条目和问题都使用相同的优先顺序去重：

1. `deadline_proximity`：任务有截止时间，或问题为 `miss_due`/`overdue`。
2. `priority`：任务的优先级参与了同一候选中的决策。
3. `energy_fit`：任务负荷与策略目标能量匹配，或低能量策略实际降低了高负荷偏好。
4. `kept_baseline`：基线条目的 ID、开始时间和时长保持不变，或策略明确将其锁定。
5. `fixed_conflict`：固定条目占用/冲突导致候选空档受限。

数组顺序固定且不得重复。固定条目也要返回 `kept_baseline`（若来自基线）或 `fixed_conflict`（若发生冲突），不能总是返回空数组。
