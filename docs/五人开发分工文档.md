## 4. 五人岗位分工

### 成员 A：项目负责人 / 架构与调度内核

**主责目标：** 保证产品主线、数据契约和调度/救援规则只有一个可信来源。

**负责目录与文件：**

- `docs/` 中的架构、接口、后端守则和决策记录。
- `backend/services_scheduling.py`，以及后续独立的 `SchedulerCore`、测试向量和基准脚本。
- `lib/services/scheduling/` 中 Dart 调度接口、策略和本地救援规则。

**必须交付：**

- 调度输入/输出 JSON 契约、稳定排序规则、问题码和解释码。
- 三种救援策略的约束与权重说明。
- Dart/Python 共享测试向量和差异报告。

**明确不负责：** 页面视觉重做、数据库迁移实现、生产服务器运维、硬件接入。

**越界禁止：** 不得在调度模块中访问网络/数据库；不得为了通过测试偷偷改变截止时间、固定日程或回滚语义；不得在没有基准数据时推动 Go/Rust/C++ 替换。

**主责目标：** 提供可校验、可追踪、可回滚的 FastAPI + SQLite 服务。

**负责目录与文件：**

**明确不负责：** Flutter 页面排版、客户端缓存策略、调度算法的第二套实现、AI/设备/第三方业务。

### 5.1 不可随意拆分的公共边界

客户端和后端必须遵循以下链路：

```text
Screen / Widget
  -> AppServices
  -> DataService
  -> CompositeDataService
  -> RemoteDataService / LocalDataService
  -> ApiClient / LocalPersistence
```

调度必须遵循以下链路：

```text
API Router
  -> Application Service
  -> SchedulerCore（纯计算）
  -> Persistence Adapter
```

任何人新增接口、字段或状态时，都必须同时更新模型、服务层、页面状态、测试和对应文档；不能只改一端。

## 6. 统一开发规则

### 6.1 数据和错误语义

- 日期统一 `YYYY-MM-DD`，时间点使用 ISO 8601，`height` 与时长保持现有兼容换算（`80.0` 约等于 60 分钟）。
- 调度先满足固定日程、工作窗口、截止时间和依赖，再做软评分。
- 事件批量写入必须拒绝空 ID、批内重复 ID 和跨用户冲突，并具备幂等性。
- 远端成功、本地模式、待同步、无数据、冲突、预留和超时必须是不同状态。
- 任何错误都要告诉用户“发生了什么”和“下一步能做什么”；不得把失败静默成空列表。

### 6.2 Reserved 边界

AI、设备/蓝牙采样、推送、第三方日历深度接入、文件/对象存储、密码重置等外部能力仍保持 Reserved/501，不允许 UI 伪装成功。

ICS 导入导出、批量日程、冲突检测、团队黄金窗口和预约会议、账号退出、基础游标同步已有后端实现，不再列为 501。基础游标接口不代表完整多端同步；持久认证与 CORS 已在本轮源码完成，生产主机切换、正式域名/TLS、PostgreSQL 与多实例仍未验收。

### 6.3 Git 与合并

- P0 完成前，不在当前混合工作树上继续大规模重构。
- 每个成员使用短分支和小提交；公共文件冲突优先由主责人合并。
- 提交信息说明行为变化；格式化、资源替换和业务修改不要混成一个不可审查提交。
- E 的验收不通过时可以阻止合并；不能通过删除测试或放宽断言解决。
- 合并前保留完整工作树状态、测试输出和已知缺口；不能声称已同步 GitHub 或已部署生产，除非有对应证据。
